## Implementation review — September 30, 2026

The calculator now uses the calm palette, local serif/sans-serif pairing, a 640px desktop reading measure, mobile side padding, concise copy, and no decorative dividing lines. Display settings provide three text sizes and System/Light/Dark appearance. Only these preferences may be stored. Result amounts remain generated by the original calculation functions; payment alternatives and lifetime/bridge components stay explicit. Nearby-year comparisons use one responsive representation. Disclosures have a 120ms opacity reveal disabled under reduced motion.

Better-layout was applied for shared edges, spacing hierarchy, logical CSS properties, and reflow. Better-ui supplied optical alignment: the calculation button has 20px text-side padding and 18px arrow-side padding. The better-typography, better-colors, better-accessibility, and better-writing skills informed typography, semantic tokens, control behavior, and copy.

| Principle | Severity addressed | Location | Before | After | Why |
| --- | --- | --- | --- | --- | --- |
| Shared edges and grouping | Medium | `styles.css:47` | Multiple padded card boundaries and layered overrides | One reading column and deliberate within/between-group gaps | Makes reading order easier to scan |
| Adaptivity and canonical presentation | Medium | `js/ui.js:50` | Wide comparison table plus a separate mobile view | One set of labeled comparison records | Removes horizontal scrolling and duplicate render markup |
| Optical alignment | Low | `styles.css:81` | Calculation action had no aligned directional cue | Trailing SVG arrow with 2px optical padding correction | Balances icon and label weight |
| Progressive disclosure and copy | Medium | `index.html:60` | Long repeated visible disclaimers and reminders | Short notice; full terms and sources in a native disclosure | Keeps essential context without competing with results |
| Accessible flow | Medium | `js/app.js:25` | Errors focused the summary; result insertion did not move focus | First invalid input receives focus; calculated result heading receives focus with a concise status update | Makes correction and result navigation predictable |
| Reading preferences | Medium | `js/preferences.js:1` | One appearance and one text size | Validated preferences, session fallback, content-node anchoring | Supports comfortable reading without storing answers |

Verification used headless Microsoft Edge 154.0.4258.37 on Windows. All 31 Node tests passed. Browser checks covered 60 combinations: 320/375/672/1024/1440px widths, all three text sizes, Light/Dark, and System with both OS schemes. Expanded content had no horizontal overflow; measured visible-text contrast was at least 5.15:1. Six axe-core 4.13.0 WCAG A/AA audits found no violations. Keyboard flow, validation, result/reset focus, reduced motion, denied/corrupt/invalid storage, direct file opening, and absence of external background requests were checked. Long titles/actions, Chinese/English/mixed-language fixtures, and an RTL mirror were checked without changing the English-only UI.

Not verified: physical iOS/Android devices, Safari/Firefox rendering, screen-reader announcements, actual browser-chrome 200% zoom, and slow-motion replay in the browser Animations panel. A half-width viewport with doubled pixel density checked equivalent zoom reflow only. Focus mode, chapters, self-tests, and saved reading position are not applicable to the current calculator. External official-source destinations were preserved but not re-audited for availability in this design pass.

Review verdict: **Approve for inspected coverage**. No unresolved high-severity findings remain in the checked coverage; unverified device and assistive-technology behavior is not included in this verdict.
